# CloudGrid Setup And Configuration

Use this skill for setup and runtime configuration tasks. Keep the work grounded
in checked-in handbook pages, runtime validation code, and deployment files; do
not invent environment variables or operator behavior.

## Source Order

Read only the files needed for the requested setup path:

1. `website/src/content/handbook/getting-started/`
2. `website/src/content/handbook/configuration/`
3. `website/src/content/handbook/reference/environment-variables.md`
4. `.env.example` and `apps/packages/definition/src/index.ts`
5. `deploy/compose/cloudgrid-local.sh`, `deploy/compose/cloudgrid.compose.yaml`, and `deploy/compose/cloudgrid.env.example`
6. `tooling/scripts/setup-local.mjs` and `tooling/scripts/dev-all.mjs`
7. `compose.yaml` for source development infrastructure

If a needed config key, auth mode, setup path, or validation rule is missing,
report it as a product gap before implementing or documenting it.

## Choose The Setup Path

Use the smallest path that satisfies the task:

| User intent | Path |
| --- | --- |
| Evaluate CloudGrid from images | Release Compose: `deploy/compose/cloudgrid-local.sh`. |
| Develop CloudGrid from source | Root `.env`, `bun run setup:local`, `bun run dev:infra`, `bun run dev:all`. |
| Share with real users | Deployed mode with `CLOUDGRID_DEPLOYMENT_MODE=deployed`, `CLOUDGRID_AUTH_MODE=sso`, SSO provider config, and invitation email config. |
| Send local telemetry to multiple projects | `CLOUDGRID_OTLP_LOCAL_PROJECT_TOKENS` generated by `bun run setup:local`. |
| Observe CloudGrid itself | Self-observability variables; deployed mode requires explicit endpoint and bearer token. |

Do not mix local and deployed auth modes. `local+sso` and `deployed+local` are
invalid combinations.

## Local Source Workflow

1. Inspect `.env.example`, `compose.yaml`, and `tooling/scripts/setup-local.mjs`.
2. Run or document:

```sh
bun install
bun run setup:local
bun run dev:infra
bun run dev:all
```

3. Use `bun run dev:seed` only after the collector and app services are ready.
4. Keep generated local bearer tokens out of logs, docs, screenshots, and final
   answers. Show token variable names, not full values.
5. Verify with the narrowest useful command. For setup script changes, include
   `bun test tooling/scripts/setup-local.test.mjs`.

## Release Compose Workflow

1. Use `deploy/compose/cloudgrid-local.sh` as the single local release entrypoint.
2. Keep `deploy/compose/cloudgrid.env.example` explicit and versioned. Do not
   switch examples to mutable `latest` unless release policy changes.
3. Run or document:

```sh
cd deploy/compose
./cloudgrid-local.sh up
./cloudgrid-local.sh status
./cloudgrid-local.sh down
```

4. Keep NATS and SurrealDB private to the compose network unless product docs say
   otherwise.
5. Verify compose file changes with `bun run release:validate`.

## Deployed SSO And Invitations

Deployed browser access is invite-controlled:

1. SSO proves identity.
2. Control-plane matches the verified provider email to a pending invitation.
3. Membership and pending project grants are applied only after SSO acceptance.
4. SMTP delivery is the normal deployed onboarding path.

Required deployed shape:

```sh
CLOUDGRID_DEPLOYMENT_MODE=deployed
CLOUDGRID_AUTH_MODE=sso
CLOUDGRID_AUTH_PROVIDERS=github
CLOUDGRID_AUTH_COMPANY_ID=acme
CLOUDGRID_SESSION_SECRET='<32-plus-byte-secret>'
CLOUDGRID_PUBLIC_URL=https://cloudgrid.example.com
CLOUDGRID_INVITATION_EMAIL_MODE=smtp
CLOUDGRID_INVITATION_EMAIL_REQUIRE_DELIVERY=true
```

For GitHub, Google, or Azure, use only the provider variables defined in
checked-in runtime validation and environment reference docs. Do not add magic-link, password-login, invite-token,
SCIM, or provider-directory sync behavior unless product behavior adds it.

## SMTP Invitation Email

When `CLOUDGRID_INVITATION_EMAIL_MODE=smtp`, configure:

- `CLOUDGRID_INVITATION_EMAIL_FROM`
- `CLOUDGRID_INVITATION_EMAIL_SMTP_HOST`
- `CLOUDGRID_INVITATION_EMAIL_SMTP_PORT`
- optional username/password, reply-to, TLS mode, timeout, max attempts, retry base

Do not put secrets in docs examples. Use placeholders. If delivery is required,
invitation creation must fail when outbox state cannot be durably recorded.
